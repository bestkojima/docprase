# 多 GT / 单 Region 对齐口径 v1

公开命令为 `scripts/issue27_alignment.py --annotation <单页标注> --document <DocumentIR> --out <报告>`。版本为 `issue27-content-alignment-1`。输入文件 SHA、原始一对一结果与补充结果同时保存；不改写输入、真值、模型输出或生产文档。

## 配对和字符记账

正文 GT 按原有 0.5 参考框覆盖阈值选择覆盖最高的 text BlockResult，允许多个 GT 指向同一最终父 Region。覆盖并列时保留候选、记为歧义，不根据转写内容选择有利配对。公式、表格、图片继续按原类型和原一对一规则计分，不把 image 当作第四种 Ovis 任务。

同一父 Region 的 GT 按冻结参考顺序拼接，使用与原口径相同的 Unicode 空白折叠。**GT 之间不添加人工字符**，输出在 GT 边界处的空格仍保守计为插入；完整参考字符分母等于原口径。最短编辑路径记录每个参考和输出字符的位置及 equal / replace / delete / insert；各 GT 的输出字符范围互不重复。边界插入归下一个 GT，尾部插入归最后一个 GT。等价编辑路径按固定优先级选取，路径是诊断配对，不是逐字人工确认的证据。

失败/partial/未执行正文的正式输出为空，计完整删除。原始输出另作诊断对齐，不能取得正式成绩。未分配到任何有效 GT 的正常 text 输出按额外插入单独计账，不能通过丢弃多余文字降低 CER。忽略项及标注范围争议保留为待核验，不能据自动对齐直接认定额外内容一定是幻觉。

行内公式仅在其父 GT 获得的输出字符范围内匹配完整数学片段；一个实际片段最多满足一个参考公式。不使用原先的任意子串命中重复计功。独立公式和表格的结构、文字及单元格位置/跨度/header 继续使用原冻结校验，不推理补标签或改答案。

不同父区域的阅读顺序按实际 DocumentIR 顺序核对；同一区域内部仅当两个参考正文分别在实际输出中唯一出现且不重叠时计顺序，否则保持未核验并计错误。不能从 GT 顺序或编辑路径推导模型已按正确顺序输出。

## 通过与限制

每页记录 GT、父 BlockResult/Region、来源 LayoutBlock、框、原始输出、状态、判断依据、字符范围和编辑操作。字符对齐有 2500 万格的内存上限，超限拒绝自动核验，不删除参考分母。

“内容已核验”要求完整正文逐字一致、公式/表格/图片项目一致、无额外 text、阅读顺序有证据。存在差异时保持待核验；自动编辑对齐不能自行排除跨栏混合、语义重复或标注争议。人工复核发现可另行记录，不修改上游真值。

新旧产物都分别计算原口径和本口径。原九项门槛的正式判定继续使用原口径；补充口径不得替代原质量关。单独重算历史产物只说明评分差异，不能声称识别改善。#25 全部原结果与失败轮次保持原样，已曝光的页面不声称为新候选的未见样本。
