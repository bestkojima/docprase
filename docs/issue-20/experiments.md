历史实验日期：2026-09-30。目标是在固定开发集上比较可复现方案，同时检查新增漏块、真实转写和内容归属。当时验收尚未完成；后续范围迁移与关闭状态见上文。

## 数据、模型与评分口径

使用 `docs/omnidocbench-20/manifest.json` 固定的20张完整原图和原始标注，运行前核对所有SHA-256。444个版面标注中有9个忽略项，评分分母为435：正文366、独立公式8、表格12、图片49；正文另含180个行内公式标注。未修订标注，也未按页面挑选预处理。这是开发集调参，不是留出集验收或官方榜单成绩。

`odb-11` 为5556×8175，`odb-17` 为5556×8125，输入均为完整原页。两页不再因1600万默认像素预算被省略：实验显式使用6400万预算，模型前缩放，识别从完整原图裁图。

PP-DocLayoutV3 MNN模型SHA-256固定为 `5f1a43441d70f6843012b47eb294bed7edd3d0ef2344f0074700a38cb2e29c67`。后处理参照固定到 PaddleX 提交 `ffb64904d23708863ff5b8da312a5cbd52a7f462`，直接执行[版面处理源码](https://github.com/PaddlePaddle/PaddleX/blob/ffb64904d23708863ff5b8da312a5cbd52a7f462/paddlex/inference/models/layout_analysis/processors.py)及[检测处理源码](https://github.com/PaddlePaddle/PaddleX/blob/ffb64904d23708863ff5b8da312a5cbd52a7f462/paddlex/inference/models/object_detection/processors.py)中的函数；移除包导入与计时装饰器，核对原文件哈希。

主指标是按正文、独立公式、表格、图片类别进行一对一 `IoU >= 0.5` 匹配的微平均F1。先最大化匹配数，再以IoU打破平局。表格内子块与行内公式按唯一归属折叠为识别任务，避免将合法子块误计为额外独立任务。模型实验和公共作业定位评分均使用父LayoutBlock原框；实际识别裁图及转写另行评分。

另外记录：同类别框并集对每个标注覆盖至少80%的数量，以及预测框与同类别标注并集相交面积不到预测框50%的数量（下表“低覆盖框”）。后者是几何误框提示，不代表已逐一裁定所有框无效。只看总分不能证明没有新增漏块。

## 预处理对照

共比较7种预处理、8档阈值 `0.15/0.2/0.25/0.3/0.4/0.5/0.6/0.7`、3种矩形处理规则，以及官方auto模式与12组归属阈值，共201个开发配置。每种输入只推理一次，原始候选与mask保存后重放不同后处理。

| 预处理 | 本地规则下最佳阈值 | F1 | 匹配标注 | 识别任务 | 覆盖≥80% | 低覆盖框 |
|---|---:|---:|---:|---:|---:|---:|
| 原参考：uint8 bicubic直缩800 | 0.25 | 0.7382 | 351 | 516 | 378 | 28 |
| 保持比例、双线性补白 | 0.15 | 0.7339 | 353 | 527 | 378 | 39 |
| 保持比例、BOX面积采样补白 | 0.2 | **0.7681** | 361 | 505 | 381 | 20 |
| BOX直缩800 | 0.15 | 0.7433 | 349 | 504 | 379 | 28 |
| BOX先缩至长边1600，再原参考直缩 | 0.2 | 0.7429 | 351 | 510 | 380 | 27 |
| 保持比例、抗锯齿bicubic补白 | 0.2 | 0.7580 | 357 | 507 | 384 | 21 |
| 保持比例、Lanczos补白 | 0.2 | **0.7627** | 360 | 509 | 381 | 21 |

完整聚合分数、逐页总分、候选/归属、新增匹配/失配清单及选型审计保存在 [layout-comparison.json](layout-comparison.json)。最终选择 **Lanczos补白、阈值0.3**，以保留原基线匹配块和避免新增正文重复为门槛，再比较F1。

重复正文几何门槛使用父子并集裁图，与正文标注按“覆盖标注面积≥50%”贪心一对一匹配；未获配但仍覆盖某正文标注≥50%的额外任务记为重复。此门槛与主指标的IoU/Hungarian不同，也不能单独证明重复转写为0；最终仍检查真实公共作业。

- BOX/0.2取得最高F1，但相对统一现行后处理的旧输入基线，新增匹配30个、失配2个。`odb-04/anno34` 是真实新增正文漏检；BOX输入的最佳相关分数约0.064，阈值降到0.15也未找回。`odb-19/anno51` 被检测为更大的正文框。
- Lanczos/0.2找回了 `odb-04/anno34`，F1为0.7627，新匹配28个、失配1个。然而真实OCR在 `odb-07` 同时识别了生日图注的完整框和子框，产生一处重复输出。该版本保留为失败对照，未作为最终示例。
- Lanczos/0.25消除了上述重复，但仍有 `odb-19/anno51` 因框变大未达IoU匹配线。几何覆盖约99.7%并不等于确认转写完整，因此不放宽原匹配块保留门槛。
- Lanczos/0.3新增匹配21个，**没有原基线标注新失配**；重复正文几何候选为0。在56个预处理/阈值组合中，另两种满足上述门槛的是原参考/0.4和原参考/0.5，F1分别为0.7372和0.7277，均低于Lanczos/0.3的 **0.7532**。

统一现行后处理的旧输入基线为18页 `reference/0.5` 加两张超大页 `letterbox_bilinear/0.5`：333个匹配、482个任务、F1为0.7263。所选Lanczos/0.3为354个匹配、505个任务、F1为0.7532，标注覆盖≥80%由348增至374，低覆盖框由23降至17。门槛在开发集反例分析后确定，仍需独立留出集复核。

原参考18页加早期两张大页的实际历史OCR作业仍单独保留；其归属规则与当前不同，不能把该历史OCR比较说成只改变插值的单变量实验。

生产MNN与直接probe的真实JPEG路径仍有数值差异：`odb-15` 的边缘 `aside_text` 候选18，probe得分0.301168，公共CLI得分0.299328，分别位于0.3阈值两侧。故直接实验为505个任务，实际公共作业为504个、F1为0.7540；两者均匹配同样354个标注，新匹配21个、失配0个。确定性模式图的张量相等不能据此推广为全部真实JPEG/推理逐值相等；该边缘候选没有覆盖有效同类标注，仍保留差异记录。公共候选重放在其自身导出的原始候选上逐页一致。

生产保留浮点NMS、短标题/注释保护和矩形识别裁图，差异不是官方等价实现。实验已执行官方auto几何参照，生产尚未实现该提取链；处理顺序、短框和合法注释保护差异继续在 [geometry-and-ownership.md](geometry-and-ownership.md) 中明确记录。

归属实验比较行内公式覆盖率 `0.7/0.85/0.9/1.0` 和表格覆盖率 `0.85/0.9/1.0`。当前保留0.85/0.9及最小唯一父框选择；要求完全包含会多出18个识别任务，匹配数不增加，F1降至0.7390。受控边界用例继续约束部分包含的合法子块；相邻文字合并始终关闭。

## 生产实现与裁图修复

两个示例配置显式设置：

```json
"execution": {
  "max_page_pixels": 64000000,
  "max_output_bytes": 67108864,
  "max_new_tokens": 512,
  "layout_preprocess": "smartresize_lanczos",
  "layout_score_threshold": 0.3
}
```

未提供这两个新字段的旧配置继续使用 `auto/0.5`。可选模式为 `reference/auto/smartresize_bilinear/smartresize_area/smartresize_lanczos`；显式smartresize模式对每页按比例缩到800画布内并补白，框/mask回映原页，识别裁图从原图取得。运行清单记录模式、阈值和预算，`input_transform.resample`记录实际插值。

面积采样与Lanczos的C++实现按[Pillow 12.3.0参照](https://github.com/python-pillow/Pillow/blob/12.3.0/src/libImaging/Resample.c)扩展核支持、归一化22位定点系数、逐轴舍入到uint8。四种尺寸100×200、801×1200、1000×2300、4100×4200的确定性彩色模式图对照均为0个不同张量浮点数；公共用例另用高频黑白条纹检验实际抗锯齿行为。

真实BOX/0.3全页作业暴露17处裁图边缘截断，涉及8页：子块虽有归属，父裁图仍取原父框。修复后父Region/BlockResult和资源裁图取父子框并集，LayoutBlock保留原框，诊断记录 `recognition_crop_bbox` 与 `owned_content_union`。8张受影响完整原页重跑后，截断数为0；其余12张旧结果只作为明确标记的未受影响复用。

代码审查进一步发现扩图可能改变栏分类，现已让阅读顺序和语义几何使用原版面框；新增受控用例检验父框右边界500、子框右边界503、页面宽1000时的双栏顺序。另增加受控用例：原框接近页面中线仍正确分栏，图片/短图注同一行的top相差1像素仍按左右排序。几何回退分栏以页面中线为界，短图注/图片先按较短框高度10%（至少2像素）的top容差生成固定行锚点排序键，避免带容差比较器破坏排序一致性；有效模型rank保持优先。最终Lanczos识别实验使用该修复版，正在重新运行全部20页。

## 真实整页识别核验

阈值0.2的20页失败对照已完成，逐页产物及执行来源见 [recognition-lanczos02.json](recognition-lanczos02.json)。正文CER由历史0.6067降至0.5824，正文匹配由287/366增至316/366，归属引用错误/裁图截断/独立公式误归属均为0；但 `odb-07/b0012` 与完整图注框输出了重复生日说明，重复正文输出为1。它未通过选型门槛，较好的CER不能抵消这一回归。

CER口径说明：本报告的字符错误率是按GT块逐一配对的整流程指标，先压缩空白，再累计Levenshtein编辑距离/标注字符数；未匹配块及非ok块均按空文本计分，即使partial块已产生部分文字也不采用。它不能直接解释为已识别字符的错误比例。Lanczos/0.3旧顺序对照共27734个标注字符、16192次编辑，CER为58.38%；其中57个未匹配块贡献5613次删除，37个公式语法校验失败的partial块按空输出贡献7246次删除，272个正常匹配块贡献3333次编辑（14875个标注字符上的CER为22.41%）。这37块的实际error全部为 `invalid_inline_formula_syntax`，已有非空文字，不能称为生成未完成；其原文对标注编辑距离为3114。若采用已有原文计分、并保留未匹配惩罚，补充原文CER为43.48%，属于另一指标，不是修复带来的提升。因此还需分别核验漏匹配、公式语法校验与正常完成转写，未匹配也不能直接判定为漏检。

Lanczos/0.3旧顺序的20页完整对照已运行成功：正文匹配309/366、正文CER为0.5838，重复正文输出为0，归属引用错误/裁图截断/独立公式误归属为0。与历史基线共同可评的3230个标注对中，新增顺序错误3对、修正3对；其中 `odb-08` 的B/C图注以及 `odb-13` 的左右图片/正文暴露1像素top抖动与中线分栏问题。修复代码后的最终整页运行另用新输出目录，不能给旧产物补标新代码版本。

最终汇总将在该20页完整作业完成后写入此节，并保存逐页产物哈希、有效参数、真实转写分数和归属审计。版面专用作业保留所有独立候选，不进行正文/表格内容归属，阅读顺序分支也可能不同；其顺序分数不能替代完整印刷页管线的验收结果。正在运行的中间产物不作为最终验收通过证据。

## 重现

实验依赖固定在 [experiment-requirements.txt](experiment-requirements.txt)。已有模型与固定数据后：

```bash
uv venv .scratch/issue20-experiments-env --python /usr/bin/python3.12
uv pip install --python .scratch/issue20-experiments-env/bin/python \
  -r docs/issue-20/experiment-requirements.txt
cmake --build build -j2
.scratch/issue20-experiments-env/bin/python scripts/issue20_compare.py \
  --out output/issue-20/experiments --polygons \
  --summary docs/issue-20/layout-comparison.json

  --cli build/dococr_cli --config configs/printed-page.example.json \
  --out output/issue-20/recognition-reproduced
.scratch/issue20-experiments-env/bin/python scripts/issue20_quality.py \
  --before output/issue-20/recognition-baseline \
  --after output/issue-20/recognition-reproduced \
  --out output/issue-20/quality-reproduced.json
```

## 剩余验收缺口

定位分数提升不代表转写准确。完整官方生产后处理契约、真实正文/公式转写与语义归属、开发集误框/漏块的内容核验，以及独立留出集复核仍需完成。Issue #20 已按用户要求被新规格替代并关闭，以上缺口迁移至 Issue #26；开发集调参、整页作业运行成功或受控测试通过仍不代表完整验收。

## 识别问题定位补充

37个正文partial均来自公式语法校验，未发现这些块有token截断。当前公式解析白名单缺少真实输出中的 `\mid`、`\cap`、`\leqslant` 等命令，并拒绝以等号结尾的题干表达 `$z=$`；须区分合法题干行内表达和独立公式的完整性约束，保留未闭合包裹与缺参检查，不能直接将全部partial升级ok。

57个正文未匹配中，29个仍被某正文裁图覆盖至少50%，但该输出已分配给另一GT块；1个被其他类别裁图覆盖，27个没有达到覆盖线。前29个存在检测粒度与GT粒度不一致，应逐项对齐原文确认是否实际包含内容，不可直接当成漏字，也不可把同一输出重复计为多个完整命中。
