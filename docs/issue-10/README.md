# Issue #10：页面阅读顺序与图文关联

本项经公共文档作业接口输出 [DocumentIR 1.3](document-ir-1.3.schema.json)。凡使用 PP-DocLayoutV3 三张量契约的 Layout-only 或 Layout+Ovis 作业均输出 1.3；旧通用 fixture 作业继续输出 1.0。已保存的 1.0、1.1、1.2 文件及 Schema 不原地更改。读取器必须按 `schema_version` 选择 Schema，不能把 1.3 当旧版解析。运行清单的 `schema_version` 是清单自身的版本，独立于 DocumentIR。

## 排序依据

先在原有稳定的几何发现次序分配块、区域和版面 ID、生成资源与识别请求；完成后只重排页面 `blocks`、`layout_blocks`、`regions`、`resources` 的展示次序以及 `reading_order` 和 Markdown。所有引用继续指向原 ID，`provenance.request_id` 从固定区域 ID 生成。内容归属先于排序确定，归属子候选保留原始框、mask 和关系。

对正常分辨率页面，用宽度至少 65% 且跨过页面中线两侧的块作为跨栏分段边界。每段若同时存在明确的左栏框（右边不超过页宽 48%）和右栏框（左边不小于 52%），先左栏后右栏，各栏按上缘与横坐标稳定排序；窄居中块排在本段两栏之后，不破坏两栏判断。跨栏块排在前一段之后、后一段之前。无法确定双栏时按页面几何排序。低于 64 像素宽的协议测试图使用简单几何顺序。当前几何规则面向近似等宽双栏与单栏，不声称解决任意多栏、旋转、嵌套浮动框或复杂页眉页脚。

模型 rank 仅在所有输出块的 rank 都存在且唯一，并且其顺序不逆转跨栏分段、左右栏或同栏中明确分离的纵向区域时采纳。非连续数值是有效顺序值，无须从 0 或 1 连续递增。`-1` 是明确缺失哨兵。重复、缺失或与版面几何冲突时使用几何顺序；`reading_order_evidence.source/reason` 和各块的 `reading_order_source` 记录实际依据，原 rank 与候选行号仍留在 Layout 诊断。完全相同的几何框按稳定输入次序打破平局，但候选行号不会替代可区分内容的阅读顺序。

## 保守关系

`figure_title` 与最近的原图裁剪资源对应的 `image/chart` 块，仅在横向相交、纵向邻近且唯一时建立 `caption_of`。带有明确编号的 `表1`、`表一`、`Table 1` 等文本在同样证据下可与表格建立 `caption_of`；“表明…”等普通正文不作为表注。邻近距离上限取区域高度及页高 3% 中较小者，且至少 8 像素。同距多个目标不关联。

`footnote` 与 `vision_footnote` 仅在正文含与脚注开头一致的完整标记（目前为 `¹`～`⁵`、`①`～`⑤` 或 `[1]`～`[5]`）、横向相交且只有一个上方候选时建立 `footnote_of`；页脚 `footer` 不据此推断为脚注。无标记、多处引用或几何证据不足时不建立关系。标题层级、图表语义与题目归属不自动猜测。关系的 `evidence` 保留采用的类别、文本标记与几何依据。图片与图表资源始终从原始页面 RGB 裁剪，并在 Markdown 中引用相对路径；未知类和过滤候选保持在诊断及资源中。

## 本地验收

`tests/reading_order_integration.py` 通过 CLI 公共作业入口检查单栏、纯双栏、中段跨栏标题、栏内图片和图注、表注与脚注、居中页脚、歧义不关联、非连续/重复/缺失 rank、模型在同一行实际改变排序、过滤及未知候选、表格内文字和公式归属、ID 与请求来源稳定，以及 Markdown 和原图资源。测试以受控 Layout 与转写结果驱动，验证编排与导出；它不证明真实模型的版面准确率或 Windows 运行。旧 Layout、公式与表格回归脚本改为按 1.3 Schema 验证当前作业输出；旧证据文件仍保持历史版本。
