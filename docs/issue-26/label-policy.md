# 后续 Issue 的标签处理契约

2026-10-01，按用户要求记录。#26 已实现三类识别映射和图片资源路由；后续 #28/#29 修改后处理、类别或过滤时沿用本契约，#27 沿用对应的内容归属与计分口径。

## 三类识别与其他标签

**Ovis 只有 text / formula / table 三种区域识别任务。DocLayout 的细分 label 是来源信息，应先统一映射，再规划区域和调度；不用为每个 label 增加一种识别任务。**

| 来源标签 | 处理方式 |
|---|---|
| 正文、标题、图注、脚注、页眉页脚、编号等文字细类 | 映射为 text；集中保留必要的版面用途提示 |
| 独立公式、未归属正文或表格的公式 | 映射为 formula |
| 已确认属于正文的内嵌公式 | 由父 text 区域一次输出，不额外调用 formula |
| 表格及其已归属文字/公式子块 | 由父 table 区域一次输出，不重复识别子块 |
| image、chart、seal 等图像资源 | 保存资源，字段类型为 image；不调用 Ovis，由 Markdown 引用保存的图片地址 |
| 明确无需保留的其他 label | 可添加显式 skip 策略，不建立 Ovis 任务 |
| 尚未支持或语义不明的 label | 当前保留原框/来源并标记 unknown；后续只有明确策略才能 skip，不默认猜成正文或静默丢弃 |

当前集中映射位于 `src/layout_region_policy.cpp`，来源类别以冻结模型配置的 class ID 为准。同名 formula、footer、header 仍保留各自原始 class ID。`regions[].recognition_type=image` 表示资源类型，并不是第四种 Ovis 识别任务；`structure_plan.recognition_order` 只含三类实际任务。

## 可以适当添加 skip

后续 Issue 可以为水印、装饰、重复外层容器或明确不需要输出的 label 添加 skip。规则保持简单：写清适用 label/class ID、跳过条件和原因，保留原始候选及处理记录；使用相关原图反例核验有效正文、图注和插图没有被一起跳过。不能仅因一个文字 label 尚未参与某种结构关联，就把它当成错误或输出大量告警。

当前 class 18 `reference` 的既有 `outer_reference` 筛选保持原样；#26 没有新增面向其他 label 的可配置 skip 功能。新 skip 策略由 #28/#29 根据实际样本实现、记录差异，并核验受影响区域。

需要区分三种情况：

- **资源不识别**：image 已成功保存，是正常输出。
- **子块不重复识别**：内容已由父 text/table 输出，来源和唯一所有权继续保留。
- **label 显式 skip**：按已记录策略不进入输出/识别流程，记录原因和适用范围。

三者都不计作 Ovis 成功或失败。已经执行但识别/校验失败的 text / formula / table 仍按原失败规则展示原图，不能改成 skip 来改善成绩。
