## 实施边界

1. 第一次 Ovis 调用前固定 Region 身份、类型、来源 LayoutBlock、原页裁图、唯一内容所有权与调度顺序，保存图片组、图注引用及规划依据。组装/导出使用同一计划，不再根据相同几何独立猜测确定关系。
2. 几何分组可在标签转写前完成，标签文字来自实际 OCR。无法确认的语义关系允许保持不确定，保存证据、原图与待核验提示；识别后可补充文字或标记冲突，不静默改写 Region、裁图及内容所有权。
3. 结构分组不合并识别裁图，相邻正文合并默认关闭。保留现有行内公式由正文输出、表格子块由表格唯一输出的规则；独立公式保留。GT 标注块与 Region 不必一一对应，正文及行内公式由同一 text Region 输出是合法粒度。
4. 本次排序/导出修复不修改现有 NMS、mask、筛选及归属策略。验证原框、裁图、rank、mask 行、过滤原因与来源未因结构规划被覆盖；以后如改裁图或归属，针对改动范围核验内容完整且不重复。
5. 保持现有串行独立会话、像素/token/时间预算、失败原图展示、公共 C ABI/CLI 和旧 JSON 兼容。DocumentIR 扩展需版本化并校验，旧文档缺少计划时不补造证据。
6. 单栏选项与真实双栏/跨栏标题保持可解释排序。以已列反例和既有公共回归验收，不要求本票实现完整语义拆题、重建全部栏结构算法或纸面横排视觉复刻。

## 标签处理逻辑与后续任务

Ovis只有 **text / formula / table** 三种区域识别任务。DocLayout的正文、标题、图注、脚注、页眉页脚和编号等文字细类先集中映射为text；独立公式映射为formula，整表映射为table。已确认属于正文的内嵌公式由父text一次输出；表格子块由父table一次输出。

image/chart/seal保存为image资源，不调用Ovis，由Markdown引用保存的图片地址。image是资源类型，不是第四种Ovis任务。其他label可在后续#28/#29中适当添加明确skip：写清适用标签、条件和原因，核验受影响有效内容；未知或不明确的来源不默认静默丢弃。资源不识别、已归属子块不重复识别、label显式skip分别记录，不计作OCR成功/失败；已执行的识别/校验失败不能改为skip来改善成绩。

统一约定已写入#28/#29/#27，详见 `docs/issue-26/label-policy.md`。#26本轮没有额外加入新的水印/装饰skip策略。
